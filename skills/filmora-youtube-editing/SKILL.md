# Filmora YouTube編集

## ローカル生成モード（既定）

ユーザーがFilmora画面での編集を求めていない場合は、FilmoraのUIを操作しない。ローカルで対応表、字幕、編集可能なWFP、概要欄、編集レポートを生成し、Filmoraはユーザーによる最終確認だけに使う。

- 音声認識はチャンネル共通のキャッシュ対応ツールを再利用する。音声が変わっていない限り再認識しない。
- 画像は、資料の番号付きディレクトリを章の候補絞り込みにだけ使う。番号・ファイル順で画像を配置しない。
- 画像OCR、画像の見出し、固有名詞、数値と、単語時刻付き音声を照合する。対応表には一致語・数値・スコア・採用理由を必須で記録する。
- 根拠が閾値未満の画像は配置せず、対応表では `blank` として記録する。周辺画像や連番画像で埋めない。
- WFP生成は既知の正常なテンプレートを土台にスクリプトで行う。非公開形式のため、生成後にFilmora UIでの自動修正はしない。
- BGMがFilmoraライブラリ内だけにある場合、ローカルWFPへ勝手に代替曲を埋め込まない。WFPに既存の正しいBGMがある場合だけ保持し、なければ編集レポートへ未配置理由を記録する。

素材をFilmoraで編集し、編集可能なプロジェクトを作る。YouTube投稿は別依頼として扱う。MP4の書き出しはユーザーが依頼した場合だけ行う。

## 編集の順序

1. 台本、音声、章別画像の対応を確認し、音声ファイルごとの担当章と実尺を確定する。複数の資料デッキがある場合は、全ページを確認して資料デッキと章の対応も確定する。
2. 音声を単語時刻付きで文字起こしし、台本全文と強制照合して、台本文面の字幕へ実音声の開始・終了時刻を移す。台本文字数による比例配分だけで字幕時刻を決めない。
3. 字幕タイムコードを基準に、各画像の見出し・固有名詞・数値と一致する発話をアンカーとして決め、画像を1枚ずつ個別クリップとして配置する。
4. 字幕の視認性と話者別スタイルを整える。
5. 画像間の60〜80%へトランジションを付ける。
6. 1枚に複数の論点がある画像へ、必要に応じて注目箇所を示すステッカーを置く。
7. ローカル生成モードでは、対応表の根拠・空白区間・WFP内部のクリップ時刻を検査してからプロジェクトを保存する。Filmora UIを操作するモードだけ、代表地点をFilmoraプレビューで目視確認する。MP4は明示的な依頼がある場合だけ書き出す。
8. 完了後に、今回の編集方針、演出数、検証結果、残る近似箇所を総評として報告する。

音声同期と画像アンカーを確定する時は、Filmoraを操作する前に [references/audio-image-sync.md](references/audio-image-sync.md) を読む。推定配置からの手戻りを防ぐため、この同期工程を省略しない。

## 素材の順序が不確かな場合

- 音声ファイル名や台本ファイル名から章順を推測しない。各音声の冒頭・各章見出し・末尾を文字起こしで確認し、実際の章順と重複区間を対応表に記録する。
- 音声に重複、章のダイジェスト、別章の混入があれば、その範囲を編集タイムラインへ入れない。次の音声ファイルの開始時刻も、除外後の実尺から再計算する。
- 各資料デッキは全ページを目視し、ページ見出しと台本の発話を対応付ける。デッキ名だけで章へ割り当てない。
- ユーザーが資料の元になった章別MD、NotebookLM、または資料URLを示した場合は、対応表に「画像ファイル → 章別MD → 資料URL」を記録して参照する。章名付きの画像ディレクトリがある場合は、その章指定を最優先する。
- 未使用ページを均等間隔や台詞順へ自動で追加しない。各ページに対応する発話アンカーがない場合は使わず、不足箇所としてレポートへ記す。
- Filmoraへ読み込む前に、対応表から「音声区間 → 章 → 資料デッキ → ページ → 発話アンカー」を先頭から末尾まで検査し、章とデッキの取り違えがないことを確認する。

## 音声と画像を合わせる

- 動画全体を一律時間で割らない。
- 先に字幕を作り、章見出し、話題転換、質問への回答、列挙項目、重要数値の開始時刻を取得する。
- 各JPEGの見出し、固有名詞、数値、グラフ主題を字幕と照合する。OCRで足りない場合は画像を目視する。
- 画像は対応する字幕の少し前か発話開始で表示し、次の画像に対応する発話まで保持する。
- 章タイトルや同じ話題が続く箇所を除き、1枚の表示は4〜10秒を目安にする。15秒を超える場合は、同じ章の別画像、拡大、強調ステッカーのいずれかで変化を付ける。
- 正確な一致が難しい場合は、章、固有名詞、重要数値の順で優先して合わせ、近似箇所を総評に記載する。
- 画像は必ず独立クリップにし、後から1枚ずつ移動・尺変更できる状態を維持する。
- 画像切替が25秒を超える時は、対応表を見直す。正しい別ページがなければ、その長さと理由をレポートへ記載し、完成扱いにする前にユーザーへ伝える。

## 音声認識の再利用

`/Users/mamoru/techmoney/tools/transcribe_with_cache.py` を使う。このツールは既存の `*_whisper_small.json` の単語数と時刻を検査し、有効な単語時刻データだけを再利用する。仮データ、発話単位だけのデータ、壊れたデータは再利用せず作り直す。音声が差し替わった場合、または明示的に精度を上げる場合だけ `--force` で再実行する。

## 完成前の必須照合

- 文字起こしの語数、音声実尺、台本文字列との照合率を対応表へ記録する。台本と実音声を照合した比率が低い、または章境界が不自然な場合は、画像配置に進まない。
- 章ごとに「台本の章見出し → 実音声の章開始 → 資料デッキの表紙 → 各ページの見出し」を先頭から確認する。資料デッキの並び順だけで章を決めない。
- 画像クリップを生成する前に、各画像について `開始時刻 / 画像ファイル / 読み上げる台詞` を含む対応表を作る。時刻の単純な均等割り当ては禁止する。

## 字幕

- 字幕の開始・終了時刻は音声認識結果を第一候補とする。音声認識が使えない場合は音声を再生し、少なくとも各発話の開始と話者交代を実音声で確認する。
- 台本の文字量による比例配分は仮配置に限る。仮配置のまま完成扱いにせず、冒頭、各章開始、音声ファイル接続部、長い発話、話者交代、末尾を再生してずれを直す。
- 一つの発話が複数字幕に分かれる場合も、次の字幕を実際の読み上げより先に出さない。無音区間と語尾を基準に終了時刻を合わせる。
- 白背景でも読めるプリセットを選ぶ。白文字を背景なしで置かない。
- Speaker 1（男性）は青色、Speaker 2（女性）は赤色を基本とする。
- 推奨は青または赤の背景ボックスに白文字。背景ボックスを使わない場合は、濃い縁取りまたは影を付けてコントラストを確保する。
- 画面下部の資料注記やロゴと重ならない位置に置く。
- 冒頭、白背景の資料、濃色背景の資料、話者切替の4条件を目視確認する。

## タイムスタンプ案内の定型画像

- 台本または字幕に「時間がない方」「気になるところだけ知りたい方」「概要欄のタイムスタンプから飛んでください」など、タイムスタンプ利用を案内する発話がある場合は、`/Users/mamoru/techmoney/assets/images/タイムスタンプ.jpeg`を表示する。
- 案内が始まる発話で表示し、案内文が終わったら次の内容に合う画像へ切り替える。前後の説明まで長く表示しない。
- 通常の章別画像と同様に独立クリップとして配置し、後から尺と位置を調整できる状態を保つ。
- 指定画像が見つからない場合だけ、代替画像を自動生成せずユーザーへ伝える。

## 素材に適切な画像がない場合

- AI画像生成で補わない。
- 同じ章の既存画像、既存画像のクロップ・拡大、注目箇所の囲み、表示時間の調整で構成する。
- それでも内容に合う画像がない場合は、無理に別内容の画像を当てず、不足する発話と時刻を編集レポートへ記録する。ユーザーから明示的に依頼された場合だけ、別途画像生成を行う。

## NotebookLMの透かし

- NotebookLM由来の画像は、Filmoraでタイムラインに置く前に右下を確認する。
- 右下のNotebookLMロゴが見える場合は、画像を軽く拡大してロゴがフレーム外になるようクロップする。拡大率は必要最小限にし、画像の見出し・数値・出典・グラフ軸を切らない。
- 右下に読み上げ対象の情報があり、拡大だけでは両立しない場合は、ロゴを残したまま完成扱いにせず、代替画像または別の演出をユーザーに確認する。
- 冒頭、各章、数値・比較表の代表フレームで、ロゴが見えていないことと、クロップで内容が欠けていないことをFilmoraプレビューで確認する。

## 株価に言及する場面

- 個別銘柄や指数の実際の値動き、上昇率、下落率、発表前後の反応に言及する場合は、公開されているWebチャートを確認し、該当期間が見える画面を取得して使用する。
- 銘柄名・ティッカー、対象期間、価格軸または騰落率、取得元が画面上で判別できる状態にする。広告、個人情報、不要なブラウザーUIは含めない。
- 台本の数値とチャート表示を照合し、一致しない場合は古い画像を使わず、台本の基準日時とデータ取得日時の差を確認する。数値を画像加工で変更しない。
- チャート画像は素材ディレクトリへ保存し、株価の発話開始から次の論点へ移るまで独立クリップとして配置する。概要欄または編集レポートへ取得元URLと取得日を記録する。
- ログイン、課金、利用規約上の制限で取得できない場合は、別の公開情報源を使う。それでも取得できない時だけユーザーへ伝える。

## トランジション

- 画像間の60〜80%に付ける。全箇所へ機械的に付けない。
- 選択に迷ったらページカールを使う。
- 章の切替、図表から図表、タイトルから本文を優先する。
- 短い画像、連続する数値表、会話のテンポを損なう箇所では省略する。
- 適用数を数え、目標範囲に入っていることを確認する。

## 注目箇所の囲み

- 1枚の画像に2つ以上の論点・数値・図があり、音声が片方だけを説明している時に使う。
- 既定はFilmoraの「ブラックフライデーネオンエレメント49」ステッカー。
- 読まれている領域を囲み、次の論点へ移ったら位置を変えるか非表示にする。
- 字幕、重要な数値、出典注記を隠さない。画面を塞ぐ場合はサイズと不透明度を下げる。

詳細な検証と報告項目は [references/quality-checklist.md](references/quality-checklist.md) を読む。
